[일정 템플릿 마켓 완성 가이드]
대상: TripPlan* (마켓) + TravelPlans* (여행계획 짜기) 연결
기준: main 최신 (2026-10-22)


■ 0. 목표

1) 공유: 내가 "여행 계획 짜기"에서 만든 계획 하나를 골라 마켓에 올린다
2) 구경: 마켓 목록/상세에서 남의 일정(일차별 장소·시간)을 본다
3) 퍼가기: 버튼 하나로 그 일정이 "내 여행 계획"에 그대로 복제된다
   → 장소 페이지(/location#plans)나 마이페이지에서 바로 보이고 수정할 수 있다


■ 1. 지금 뭐가 문제인가 (실제 코드 확인함)

- 마켓(TripPlan)과 여행계획(TravelPlans)이 완전히 따로 논다
  마켓 글을 쓸 때 일차/장소를 손으로 따로 입력해야 하고, 내가 짠 계획을 고를 방법이 없다
- 퍼가기(TripPlanService.fork)가 "내 여행 계획"이 아니라 마켓 글을 하나 더 만든다
  → 퍼가도 여행 계획 짜기 화면에는 안 나온다
- fork 로 만든 글에 작성자(member)를 안 넣는다 → 주인 없는 글이 생긴다
  (컨트롤러가 principal.getName() 을 넘기는데 서비스에서 안 씀)
- 퍼가기 수(tripplanShareCount)가 안 올라간다
- getEntity() 에러 문구가 "자유게시글을 찾을 수 없습니다" (복붙 흔적)


■ 2. 이번에 정하는 규칙 세 개

(1) 마켓 글은 공유하는 순간의 "스냅샷"을 저장한다
    원본 계획(TravelPlans)을 그대로 참조하지 않는다
    이유: 작성자가 나중에 자기 계획을 고치거나 지우면 마켓 글이 같이 바뀌거나 깨진다
    → 이미 있는 TripDay / TripPlace 테이블을 스냅샷 저장용으로 쓴다

(2) 마켓에는 날짜를 저장하지 않는다. "1일차, 2일차"만 남긴다
    남의 10월 24일 일정을 퍼가도, 나는 내 날짜로 가야 하니까
    → 퍼갈 때 "출발일"만 받아서 날짜를 새로 계산한다

(3) 퍼가기 결과는 TravelPlans 에 만든다 (마켓 글을 또 만들지 않는다)
    퍼간 일정은 완전히 내 것. 원본 글이 지워져도 내 일정은 남는다


■ 3. 구조 이해

  [여행 계획 짜기]                 [템플릿 마켓]                  [여행 계획 짜기]
  TravelPlans (작성자)   --공유-->  TripPlan                --퍼가기-->  TravelPlans (퍼간 사람)
   └ DailyPlans (날짜)              └ TripDay (N일차)                  └ DailyPlans (출발일+N-1)
      └ SchedulePlans (장소·시간)      └ TripPlace (장소·시간)            └ SchedulePlans

  공유 = TravelPlans → TripPlan 으로 복사 (날짜 빼고)
  퍼가기 = TripPlan → TravelPlans 로 복사 (날짜 새로 계산)
  둘 다 "복사"다. 서로 참조하지 않는다


■ 4. 엔티티 고치기

--- TripPlanEntity (추가)
    private Long sourcePlanId;      // 어느 계획에서 공유했는지 (참고용. FK 아님. 원본이 지워져도 괜찮게)
    private Integer tripplanDays;   // 몇 박 며칠인지 (목록에 "2박 3일" 표시용)
    private String tripplanType;    // 원본 planType (여행 유형)

--- TripDayEntity
    tripDayNumber 를 String -> Integer 로 (정렬·날짜 계산에 쓴다)
    @OrderBy("tripPlaceSequence") 를 tripPlaces 에 추가

--- TripPlaceEntity
    locationId(Long) -> 장소 엔티티 연관관계로 바꾼다 (상세에서 장소 이름·주소를 보여줘야 하니까)
        @ManyToOne(fetch = FetchType.LAZY)
        @JoinColumn(name = "location_id")
        private LocationEntity location;
    tripPlaceSequence 를 String -> Integer 로
    추가: private String tripPlaceStartTime;
          private String tripPlaceEndTime;
    tripPlaceMemo 는 그대로 (SchedulePlans 의 scheduleDescription 을 담는다)

※ 타입을 바꾸면 ddl-auto=update 가 기존 trip_* 테이블 컬럼을 못 바꿀 수 있다.
  지금 마켓 데이터는 테스트용뿐이니 trip_place, trip_day, trip_plan 세 테이블을 DROP 하고 다시 띄우는 게 제일 깔끔하다.
  (지우기 전에 팀에 한 번 말하기)

DTO 도 같은 이름으로 맞춘다 (TripDayDTO, TripPlaceDTO).
TripPlaceDTO 에는 화면 표시용으로 locationName, locationAddress 를 추가한다.


■ 5. 공유하기 (마켓에 올리기)

--- 화면: tripplan/insert.html
지금의 일차/장소 손입력 칸을 지우고 "내 여행 계획 선택" select 하나로 바꾼다
    <select name="sourcePlanId" required>
        <option value="">공유할 여행 계획을 고르세요</option>
        <option th:each="p : ${myPlans}" th:value="${p.planId}"
                th:text="${p.planTitle} + ' (' + ${p.planStartDate} + ' ~ ' + ${p.planEndDate} + ')'"></option>
    </select>
제목 / 소개글(tripplanContent) / 공개 여부는 그대로 둔다
내 계획이 하나도 없으면 "여행 계획 짜기에서 먼저 계획을 만들어 주세요" 안내 + /location#plans 링크

--- 컨트롤러: GET /tripplan/insert
    model.addAttribute("myPlans", travelPlansService.getTravelPlanList(details.getMember().getMemberId()));

--- 서비스: TripPlanService.insert(memberId, dto)
    1) 원본 계획을 "내 것인지" 확인하면서 가져온다
       TravelPlansEntity source = travelPlansRepository
               .findByPlanIdAndMemberId(dto.getSourcePlanId(), memberId)
               .orElseThrow(() -> new IllegalArgumentException("내 여행 계획만 공유할 수 있습니다."));
       ※ 남의 planId 를 F12 로 넣어 보내는 경우를 막는 줄. 빼면 안 된다

    2) TripPlanEntity 를 만들고 제목/소개/공개여부/작성자/sourcePlanId/tripplanType 세팅

    3) 일차별로 복사 (날짜는 버리고 번호만)
       for (DailyPlansEntity daily : source.getDailyPlans()) {      // dailyNumber 순서
           TripDayEntity day = new TripDayEntity();
           day.setTripDayNumber(daily.getDailyNumber());
           day.setTripPlan(plan);

           for (SchedulePlansEntity s : daily.getSchedulePlans()) {   // @OrderBy scheduleNumber
               if (s.getLocation() == null) continue;                 // 장소 없는 일정은 건너뜀
               TripPlaceEntity place = new TripPlaceEntity();
               place.setLocation(s.getLocation());
               place.setTripPlaceSequence(s.getScheduleNumber());
               place.setTripPlaceStartTime(s.getScheduleStartTime());
               place.setTripPlaceEndTime(s.getScheduleEndTime());
               place.setTripPlaceMemo(s.getScheduleDescription());
               place.setTripDay(day);
               day.getTripPlaces().add(place);
           }
           plan.getTripDays().add(day);
       }
       plan.setTripplanDays(source.getDailyPlans().size());

    4) 장소가 하나도 없는 계획이면 막는다
       "장소가 하나 이상 들어간 계획만 공유할 수 있어요."

    5) tripPlanRepository.save(plan)  (cascade 로 Day/Place 같이 저장)

※ dailyPlans 순서 보장: DailyPlansEntity 쪽 컬렉션에 @OrderBy("dailyNumber") 가 없으면
  TravelPlansEntity.dailyPlans 에 @OrderBy("dailyNumber") 추가 (재희씨 파일이니 말하고 추가)


■ 6. 목록 / 상세

--- 목록 (tripplan/list.html)
    공개(tripplanIsPublic = true) 글만 보여준다 → 리포지토리에 findByTripplanIsPublicTrueOrderByTripplanIdDesc()
    카드에 보여줄 것: 제목, 작성자, "2박 3일"(tripplanDays-1 박 tripplanDays 일), 여행 유형, 퍼간 수

--- 상세 (tripplan/read.html)
    일차별로 장소 목록:
      1일차
        1. 해운대 해수욕장  10:00~12:00  (부산 해운대구 ...)
           메모: 아침 산책
    장소 이름·주소는 TripPlace.location 에서 꺼낸다
    → 상세 조회는 fetch join 으로 한 번에 가져온다 (N+1 방지)
       @Query("SELECT DISTINCT p FROM TripPlanEntity p " +
              "LEFT JOIN FETCH p.tripDays d " +
              "WHERE p.tripplanId = :id")
       장소까지 한 번에 묶으면 MultipleBagFetchException 이 날 수 있으니
       Day 까지만 fetch join 하고 Place 는 @BatchSize(size = 100) 로 묶어 가져온다
       (TripDayEntity.tripPlaces 위에 @BatchSize(size = 100))

    버튼:
      작성자 본인 → 수정 / 삭제
      그 외 로그인 사용자 → [내 일정으로 퍼가기]
      비로그인 → 퍼가기 누르면 로그인으로


■ 7. 퍼가기 (핵심)

--- 화면: 상세의 퍼가기 버튼 → 출발일 입력 모달
    <form th:action="@{/tripplan/fork/{id}(id=${tripPlanDto.tripplanId})}" method="post">
        <label>출발일</label>
        <input type="date" name="startDate" required>
        <button class="btn btn-primary">내 일정으로 가져오기</button>
    </form>
    (th:action 이라 CSRF 자동. 그냥 action 쓰면 403)

--- 컨트롤러: POST /tripplan/fork/{id}
    Principal 말고 다른 컨트롤러처럼 @AuthenticationPrincipal MemberDetails 로 받는다
    details == null 이면 redirect:/login
    성공 → redirect:/location#plans  (퍼간 계획을 바로 볼 수 있게)
           flash: "내 여행 계획에 담았어요. 여행 계획 짜기에서 확인하세요."

--- 서비스: TripPlanService.fork(tripPlanId, memberId, LocalDate startDate)  @Transactional
    1) 원본 마켓 글 조회. 비공개 글이고 내 글이 아니면 막는다
    2) 새 TravelPlansEntity 를 만든다
         member         = 퍼가는 사람
         planTitle      = 원본 제목 + " (퍼옴)"
         planType       = 원본 tripplanType
         planDescription= "템플릿 마켓에서 가져온 일정입니다."
         planStartDate  = startDate.toString()
         planEndDate    = startDate.plusDays(days - 1).toString()
    3) 일차/일정 복사 — 날짜를 새로 계산하는 게 포인트
         for (TripDayEntity day : 원본.getTripDays()) {
             DailyPlansEntity daily = DailyPlansEntity.builder()
                     .travelPlan(newPlan)
                     .dailyNumber(day.getTripDayNumber())
                     .dailyDate(startDate.plusDays(day.getTripDayNumber() - 1))
                     .schedulePlans(new ArrayList<>())
                     .build();
             for (TripPlaceEntity p : day.getTripPlaces()) {
                 daily.getSchedulePlans().add(SchedulePlansEntity.builder()
                         .dailyPlansEntity(daily)
                         .location(p.getLocation())
                         .scheduleNumber(p.getTripPlaceSequence())
                         .scheduleStartTime(p.getTripPlaceStartTime())
                         .scheduleEndTime(p.getTripPlaceEndTime())
                         .scheduleDescription(p.getTripPlaceMemo())
                         .build());
             }
             newPlan.getDailyPlans().add(daily);
         }
       ※ @Builder 를 쓰면 필드 초기값(= new ArrayList<>())이 무시돼 null 이 된다.
         그래서 위처럼 .schedulePlans(new ArrayList<>()) 를 꼭 넣는다
         (또는 엔티티 필드에 @Builder.Default)
    4) travelPlansRepository.save(newPlan)  (cascade 로 Daily/Schedule 같이 저장)
    5) 퍼간 수 +1
         원본.setTripplanShareCount(원본.getTripplanShareCount() + 1);
         (같은 트랜잭션이라 변경감지로 UPDATE 됨. save 따로 안 불러도 된다)
    6) 새 planId 반환

    지금 있는 fork() 의 "마켓 글 복사" 코드는 전부 지운다


■ 8. 수정 / 삭제

- 수정: 제목, 소개글, 공개 여부만 고친다. 일정 내용은 못 고친다 (스냅샷이니까)
  일정을 바꾸고 싶으면 → 삭제하고 다시 공유 (안내 문구로 표시)
  (여유 있으면 "원본 계획으로 다시 불러오기" 버튼: sourcePlanId 로 5번을 다시 돌려 Day/Place 를 갈아끼움)
- 삭제: TripPlan 만 지운다. 이미 퍼간 사람들의 TravelPlans 는 그대로 남는다 (복사본이라)


■ 9. 작업 순서

1) trip_* 테이블 DROP 공지 → 엔티티/DTO 수정 (4번)
2) 공유하기 (5번) → 마켓에 글이 올라가는지 DB 로 확인
3) 목록/상세 (6번)
4) 퍼가기 (7번) → /location#plans 에서 퍼간 계획이 보이는지 확인
5) 수정/삭제 정리 (8번)

TravelPlans 쪽(재희씨 파일)은 @OrderBy 추가 말고는 건드리지 않는다.
퍼가기는 TripPlanService 안에서 TravelPlansRepository 로 저장만 한다.


■ 10. 확인 체크리스트

공유
  [ ] 여행 계획 셀렉트에 내 계획만 나온다
  [ ] F12 로 sourcePlanId 를 남의 번호로 바꿔 보내면 "내 여행 계획만 공유할 수 있습니다"
  [ ] 장소 없는 계획은 공유가 막힌다
  [ ] 공유 후 원본 계획을 수정해도 마켓 글 내용은 안 바뀐다
목록/상세
  [ ] 비공개 글은 목록에 안 나온다
  [ ] 상세에 일차별 장소 이름·시간·메모가 순서대로 나온다
퍼가기
  [ ] 출발일 2026-11-01 로 2박3일을 퍼가면 일차 날짜가 11/01, 11/02, 11/03
  [ ] /location#plans 드롭다운에 "(퍼옴)" 계획이 보이고, 상세 일정이 원본과 같다
  [ ] 퍼간 수가 1 올라간다
  [ ] 원본 마켓 글을 삭제해도 퍼간 내 계획은 남아 있다
  [ ] 비로그인으로 퍼가기 → 로그인 페이지


■ 자주 막히는 것

퍼갔는데 상세 일정이 비어 있음
  → @Builder 로 만든 DailyPlans 의 schedulePlans 가 null. 7번 ※ 참고
일차 순서가 뒤섞여 나옴
  → @OrderBy 누락 (TravelPlans.dailyPlans / TripDay.tripPlaces)
상세에서 장소 이름이 null
  → TripPlace 가 아직 locationId(Long) 이거나, 장소를 LAZY 로 세션 밖에서 꺼냄.
    서비스(@Transactional) 안에서 DTO 로 다 옮긴 뒤 넘긴다
퍼가기 시 403
  → form 이 th:action 이 아님 (CSRF)
LazyInitializationException
  → 컨트롤러에서 엔티티를 직접 만짐. 서비스 안에서 DTO 변환까지 끝낸다
